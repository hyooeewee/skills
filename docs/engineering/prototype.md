## 它做什么

`prototype` 编写**回答某个问题的临时代码**——这个状态模型是否合适，或者这个屏幕应该长什么样。问题优先，并决定后续所有内容的形式；回答错误问题的原型，无论看起来多好，都是纯粹的浪费。

临时是对代码*编写方式*的约束，而不是销毁它的承诺。没有测试，没有超出运行所需范围的错误处理，没有抽象，没有持久化——因为这些都无法帮助你学到你想学的那件事。留存下来的是答案，被融入真实代码，以及原型本身，停放在 main 之外的分支上，作为答案来源的证据。

## 何时使用它

输入 `/prototype`，或者当任务合适时，[agent](https://www.aihero.dev/ai-coding-dictionary/agent) 会自动使用它。

当你遇到无法通过交谈解决的问题时，就使用它——一个你无法在脑中掌握其边界情况的状态机，一个直到你并排看到三个版本才能想象出来的屏幕。在这些问题上，[Grilling](https://www.aihero.dev/ai-coding-dictionary/grilling) 会话会迅速膨胀：agent 换着说法，你猜测，范围不断扩大以填补不确定性。停止盘问，构建临时版本，看看它，然后用一行字回答。如果相反，已构建的东西行为异常而你想知道原因，请使用 [diagnosing-bugs](https://aihero.dev/skills-diagnosing-bugs)——原型设计探索的是要构建什么，而不是已构建的东西为什么坏了。

你也会在不经意间来到这里。[wayfinder](https://aihero.dev/skills-wayfinder) 在其地图上归档 `prototype` 决策 [tickets](https://www.aihero.dev/ai-coding-dictionary/ticket)，处理其中一个 ticket 就是本技能。

## 两个分支

问题决定分支，而各个分支产生截然不同的产物：

* **"这个逻辑/状态模型感觉对吗？"** — 一个**可共享的单个 HTML 文件**。一个自包含的页面，无需构建、无需服务器，双击即可打开。它带有一个带标签的状态面板，每次点击后都会重新渲染；还有自由操作按钮，可以按任意顺序戳弄模型；以及带标签页的**引导式演练**——每个标签页一个场景，每个场景下方都有按顺序要按的按钮。所有内容都用领域语言标注，因此你可以把它交给设计师、产品经理或领域专家，让他们自己感受这个模型。页面背后的逻辑是一个小型纯模块——一个 reducer、一个状态机、一组函数——保持与 DOM 无关，以便经过验证的版本可以直接移植到真实代码中。
* **"这应该长什么样？"** — 同一个路由上的几个**截然不同**的 UI 变体，可通过浮动底部栏和 `?variant=` URL 参数切换。变体必须在结构上不同，而不是颜色上；三个微调过的卡片网格是壁纸，不是原型。只要可能，它们就在真实页面中渲染，使用真实数据和真实密度，因为在真空中评判的变体看起来总是很好。

两者都将状态保存在内存中，开始时无需思考，并在每个步骤之后向你展示完整状态。当你发现自己开始加固其中一个——添加测试、连接真实数据库、为以后可能需要的场景做泛化——你就已经不是在原型设计了。

## 原型是一手来源

一个完成的原型留下两样东西，它们去向不同的地方。

**答案**——结论加上它所解决的问题——被持久化地记录：一条提交信息、一份 ADR、一个实现 issue。这就是 main 分支所保留的，融入真实代码之中。

**原型**是答案来源的可运行证据，它不会被删除。它也不属于 main——那里没有什么需要维护的，而且它会很快腐烂——所以它被提交到 main 之外的一个临时 `prototype/<name>` 分支，永远不会合并，并在实现 issue 上留下指向该分支的 [context pointer](https://www.aihero.dev/ai-coding-dictionary/context-pointer)。main 保持干净；探索对下一个接手工作的人来说保持可查找、可重新运行。

## 常见问题

**等等——原型不是应该被删除吗？**
现在不再是这样了。过去是：构建它，保留答案，丢弃代码。对此最尖锐的反对从来不是关于速度——而是*下一个 [session](https://www.aihero.dev/ai-coding-dictionary/session) 接手工作的人是谁，他们能依据什么开展工作？* 一个原型的文字摘要会失去让它有说服力的东西。所以原型现在被视为[一手来源](https://www.aihero.dev/ai-coding-dictionary/primary-source)：它被放置在 main 之外的一个 `prototype/<name>` 分支上，实现 issue 指向它。改变的是代码存放的位置，而不是纪律——它仍然永远不会合并到 main。

**它过去构建一个终端应用。那个去哪了？**
逻辑分支现在改为产出一个可共享的单个 HTML 文件。终端应用只能由克隆了仓库并安装了运行时的人来驱动，而这恰恰排除了原型所需要的意见人群——设计师、产品经理、知道状态模型应该表达什么含义的领域专家。一个双击即可打开且能通过电子邮件发送的自包含文件，任何人都能驱动。底层的纯逻辑模块没有改变，它仍然是可以移植到真实代码中的部分。

**有一个 agent 告诉我要 `/prototype`，而我当时应该在实现功能。**
已知问题，这是一个命名问题。`prototype` 是一个通用且吸引人的词，对于不了解流程的 agent 来说，一旦存在 tickets，它就会被理解为"显而易见的下一步"，所以即使设计已经在对话中完全确定，它也会被按名字推荐。如果你已经知道要构建什么，下一步就是按 ticket 执行 `/implement`。只有当某个具体的设计问题真正悬而未决且交谈无法解决时，才使用原型。

**我是否应该在构建任何生产功能之前先对整个应用做原型——比如说，向潜在客户演示？**
那是另一个戴着本技能名字的产物。这里的原型被限定在一个问题上，"整个应用是什么样的？"不是一个问题。一个全应用原型没有自然的停止点，所以它会凭借惯性变成生产应用：清理永远不会发生，在原型规则下编写的代码——没有测试、没有错误处理——最终会出现在用户面前。如果你需要销售演示，就刻意把它作为演示来构建，并明确说明其中没有任何东西是生产级的。如果你需要解决一个设计问题，就把它缩小到那个问题。

**我如何在自己的会话中运行它？**
原型存在于自己的目录中，并产生大量你不想留在提问线程中的 [context](https://www.aihero.dev/ai-coding-dictionary/context)，所以在其他地方运行它，只带回答案。[handoff](https://aihero.dev/skills-handoff) 是双向的桥梁。

**这不是消耗 token 最快的方式吗？**
可能是的，如果你对本来可以通过交谈回答的问题做原型，或者让一个原型蔓延到整个功能。重要的比较不是 token 对零；而是 [tokens](https://www.aihero.dev/ai-coding-dictionary/token) 对比构建了错误的状态模型然后在它有了生产调用者之后才发现。保持问题窄小、运行短暂，花费就会保持合理。

## 如果它起作用了

* 你能用一句话说出这个原型要回答什么问题——而且它写在演示的顶部，而不仅仅是在你的脑子里。
* 一个不读代码的人也能驱动逻辑演示。他们打开文件，在演练标签页中按下按钮，并用他们自己的话描述所见。
* 有人说"等等，那不应该可能"或"嗯，我以为 X"。这是*想法*中的 bug，而这正是全部意义所在。
* UI 变体在布局和信息层级上不同，而不仅仅是颜色和文案——你得到的反馈是"用 B 的页眉配上 C 的侧边栏"。
* 它在一口气之内得到回答。如果一天后你还在构建它，那问题太大了；把它拆开。
* 当它结束时，main 包含决策而不包含任何原型，实现 issue 指向仍然保存着它的分支。

## 它在系统中的位置

`prototype` 是一个**随时可用的独立技能**——你进入它来解决一个设计问题，然后退出——它也是另一个技能所依赖的机制。

它最大的消费者是 [wayfinder](https://aihero.dev/skills-wayfinder)。wayfinder 地图由**决策 tickets** 组成，而 `prototype` 是 ticket 的四种类型之一：当阻塞性的问题是"这应该看起来怎么样"或"这应该怎么表现"时使用它，这些问题再多的讨论也无法解决。wayfinder 通过创造具体可反应的东西来提高模糊讨论的保真度，而本技能就是构建那个具体东西的方法。一个原型 ticket 由答案解决，原型作为资产从地图上链接。

其他邻居位于其上游和下游。[grill-me](https://aihero.dev/skills-grill-me) 和 [grill-with-docs](https://aihero.dev/skills-grill-with-docs) 回答可拷问的问题；不可拷问的问题则来到此处，而一行答案会回到访谈中。下游，经过验证的状态模型或 UI 方向成为 [to-spec](https://aihero.dev/skills-to-spec) 的既定输入，后者可以内嵌原型产生的富含决策的片段，而不是用散文描述。至于其他任何问题，[ask-matt](https://aihero.dev/skills-ask-matt) 会将你路由到整个集合。
