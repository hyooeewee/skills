## 它做什么

`improve-codebase-architecture` 会调查代码库以寻找**深化机会**。这些是浅层模块（接口几乎与它隐藏的事物同等复杂）可以变为深层模块的地方。它将这些机会写成独立的 HTML 报告，然后对你选择的一个进行[烤问](https://www.aihero.dev/ai-coding-dictionary/grilling)。

它绝不修改代码。一次完整运行会在你的操作系统临时目录下产生一段对话和一个 HTML 文件。你稍后在另一个[会话](https://www.aihero.dev/ai-coding-dictionary/session)中，通过正常的构建流程进行重构。这使它成为一个调查工具，而非重构工具，因此你可以在尚未准备好动手的代码库上运行它。

两个过滤器防止报告变成通用的清理建议。首先，每个候选必须通过**删除测试**：如果你移除这个模块，其复杂度会转移到更小的接口后面，还是分散到调用者中？只有前一种情况才会获得一张卡片。其次，除非你指定某个具体区域，它会先读取近期提交历史，将扫描重点放在频繁变更的路径上。没人碰的代码里的深化，是永远收不回成本的重构。

## 何时使用它

你通过输入 `/improve-codebase-architecture` 来调用它；[代理](https://www.aihero.dev/ai-coding-dictionary/agent)不会自行使用它。

它不是主构建循环中的一个步骤。你定期运行它，以排期更多改善代码库的工作。人们在四种情况下使用它：

| 情况     | 如何使用                                                                                                                                                                               |
| ------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 日常维护   | 每隔几天运行一次，或在你有空闲时运行，这样结构就不会在特性之间腐败。                                                                                                                                                 |
| 大型构建之前 | 将它指向 [规格说明](https://www.aihero.dev/ai-coding-dictionary/spec)将它指向\[规格说明]\(https\://www\.aihero.dev/ai-coding-dictionary/spec)，并问“如何让这次变更变得容易？”这是对它最高效的提示词。                         |
| 存量代码审计 | 在大型、缺乏结构或 [vibe-coded（凭感觉编码的）](https://www.aihero.dev/ai-coding-dictionary/vibe-coding)在大型、无结构或\[凭感觉编码的]\(https\://www\.aihero.dev/ai-coding-dictionary/vibe-coding)仓库上运行它，以了解其现状。 |
| 遗留测试工作 | 用它在针对不可测试代码编写测试前，找出缺失的接缝。                                                                                                                                                          |

它与同类技能容易混淆之处：

* 要设计一个你已选定的模块，请使用[codebase-design](https://aihero.dev/skills-codebase-design)。本技能负责找到要处理的模块，而 `codebase-design` 是你设计它的地方。
* 对于大到一个会话装不下的整体工作，请使用 [wayfinder](https://aihero.dev/skills-wayfinder)。
* 针对“这个具体东西坏了”，请使用[diagnosing-bugs](https://aihero.dev/skills-diagnosing-bugs)。当真正的发现是没有好的接缝来锁定 bug 时，它会把你送回这里。

## 先决条件

运行它无前置条件。若存在 `GLOSSARY.md` 或 `docs/adr/` 下的 ADR，它会读取它们并使用你领域自己的名词。候选项就会变成“深化订单接单模块”，而不是“重构 FooBarHandler”。

它在两处写入。报告输出到 `<tmpdir>/architecture-review-<timestamp>.html`，位于仓库之外。在烤问循环中，它会在 `GLOSSARY.md` 中添加或细化术语，若文件不存在则创建。它还会提议将被拒绝的候选记录为 ADR，以便未来的运行不再建议它。

## 深度，以及追寻深度的报告

本技能建立在一个核心概念上：**深度**。深层模块将大量行为放在一个小而稳定的接口后面。浅层模块通过接口暴露其实现，接口几乎与底层代码一样宽。报告寻找三种浅层形式：

* 仅为可测试性而提取的纯函数，而真正的 bug 在于调用者如何使用它们（无**局部性**）。
* 跨越其**接缝**泄漏的模块。
* 一个不打开五个文件就无法理解的概念。

针对每一种，它都会提出修复它的深化方案。

每个候选是一张卡片，包含涉及的文件、摩擦点、通俗易懂的解决方案、以**局部性**和**杠杆**为衡量的收益、前后对比图，以及一个强度徽章。

| 徽章                | 对你的意义                         |
| ----------------- | ----------------------------- |
| `Strong`          | 删除测试明确通过，且摩擦是真实存在的。请认真对待这些候选。 |
| `Worth exploring` | 看起来合理的深化，但收益取决于代码下一步的走向。      |
| `Speculative`     | 为完整性而包含。你可以忽略大多数这类候选。         |

报告以**首选推荐**结束，即它会优先做的那个候选。随后技能停止，询问你想探索哪个候选。此时你尚未做任何决定，也没有任何代码被修改。

## 选定一个之后会发生什么

当你选定一个候选，会针对它启动一个[烤问](https://aihero.dev/skills-grilling)会话。它涵盖约束条件、什么放在接缝后面、哪些测试保留、深化后的接口应是什么样。该会话的产出是一个决策，而非差异。此后走正常流程：将决策带入[to-spec](https://aihero.dev/skills-to-spec)，再到[to-tickets](https://aihero.dev/skills-to-tickets)，最后到[implement](https://aihero.dev/skills-implement)。

## 常见问题

**它针对一个想法盘问了我一个小时，而不是向我展示选项。我能关掉这个功能吗？**

可以。调用时说一声即可（“别烤我，只给报告”）。这是对本技能最常见的抱怨。一位用户曾喜欢它“获得彻底改进分析的便捷方式”，但加入烤问循环后，发现它“几乎不可用”。在他们的会话中，它提出单一解法，然后问“几十个或上百个问题”。设计意图是报告在前，烤问仅在你选定的候选上开始。但较弱的[模型](https://www.aihero.dev/ai-coding-dictionary/model)会直接跳到对第一个想法的面谈。不同模型下结果差异很大。这是一个开放问题，本技能尚无文档化的无烤问模式。

**报告打开时是无样式、没有图表的原始 HTML。发生了什么？**

报告从 CDN 加载 Tailwind 和 Mermaid，因此打开时需要网络访问。若有东西拦截这些脚本，页面会无报错地损坏。已报告的案例中，安全钩子要求 SRI 哈希。代理添加了它们，但 CDN 传给浏览器的字节与计算哈希时 `curl` 拿到的不同，导致浏览器拦截脚本。离线和受限环境有相同问题。代理看不见，因为它从不渲染页面。变通方法是要求内联 CSS 和手工制作的 SVG 图表，而非 CDN 方案。这是一个开放问题。

**它给了我十二个候选。我应该在同一个会话中逐个处理，还是新开一个会话？**

每个会话处理一个候选。若在一次对话中处理多个，[上下文窗口](https://www.aihero.dev/ai-coding-dictionary/context-window)会同时塞入报告、烤问、领域模型编辑和代码变更。报告只是临时文件，所以带着候选前进，别带着文件。选一个，烤问它，把决策带入 `/to-spec`。其余的转成[tickets](https://www.aihero.dev/ai-coding-dictionary/ticket)，稍后分别拾起。把选定的改进放入规格说明，而不是直接去实现。大家常问这点，但技能本身未给出工作流文档。

**我应该如何给它提示词？**

用你接下来要构建的东西提示它。若有大型构建即将到来，指向规格说明并问“如何让这次变更变得容易？”不带提示词的运行会自行寻找热点。这对日常维护没问题，但有方向能让报告可执行。

**它适用于大型遗留代码库吗？**

部分适用。它在缺乏一致结构的大型现有代码库上效果很好，也是任何一次性结构建立后的推荐维护工具。但失控项目的用户反馈“帮了点忙，但似乎还是不够用”。一位拥有八年历史遗留代码库的开发者报告模型陷入循环，而同一技能在整洁仓库上能产出清晰图谱。针对这种情况尚无专门的 `/refactor` 技能。若代码库缺乏共享词汇，请先运行[grill-with-docs](https://aihero.dev/skills-grill-with-docs) 建立一套。这通常能让本技能的输出好得多。

**本技能在哪些方面不同于 `/codebase-design`？**

`/codebase-design` 是参考资料，而非会话驱动器。它提供词汇（模块、接口、深度、接缝、适配器、杠杆、局部性），本技能使用它。若你给全新的代理以 `/codebase-design` 为任务，它会按已知方式失败。它没有自己的流程可循，所以代理会自行发明流程，再次探索代码，运行很久才会问你任何事。请运行本技能，让它去用那一个。

**它到底会不会告诉我代码库没问题？**

极少，所以开始前请知悉。本技能的存在是为了输出发现，所以倾向于产出候选，而不是得出“一切正常”的结论。用强度徽章来校正这一点。如果报告里每个候选都是 `Speculative`，说明技能什么也没发现。

**它在 Codex 或其他 harness 中能工作吗？**

部分支持。探索步骤直接调用 Claude Code 的 `Agent` 工具并设置 `subagent_type=Explore`。缺少该工具的 [harness](https://www.aihero.dev/ai-coding-dictionary/harness) 可能会跳过并行探索，而不是使用自己的替代方案。技能仍可运行，但扫描不够彻底。有人提出了与 harness 无关的重写方案，但尚未合并。

**我究竟该如何在 TypeScript 中实现深模块？**

该技能没有提供一个好的答案。人们经常要求提供一份包含具体文件和模块布局的 `TYPESCRIPT.md` 来说明这些原则，但这份文档不存在。技能会告诉你深化属于何处、什么该放在缝合面后面。你必须自行将其转化为包或目录结构。

## 如果它起作用了

* 候选者使用你的领域概念命名，而不是编造的类名：“订单录入模块”，而不是“FooBarHandler”。
* 候选项位于你最近编辑过的文件中，而非无人问津的仓库角落。
* 运行期间没有任何代码被改动。唯一的新文件就是临时目录中的 HTML 报告。
* 生成报告后停止，并询问你想要哪个候选项。不会自动继续执行。
* 每张卡片都解释收益是局部性还是杠杆作用，并指出哪些测试会变得更简单，而不仅仅是“这更整洁”。
* 当你因长期原因拒绝某个候选项时，它会提议记录一份 ADR，以便下次运行不再建议该项。

## 它在系统中的位置

`improve-codebase-architecture` 是**定期维护**任务。你每隔几天运行一次，不在任何链式流程中，目的是排期工作而非执行工作。它的相邻技能：

* [codebase-design](https://aihero.dev/skills-codebase-design) 拥有每个候选项都使用的深度与缝合面词汇表。
* [grilling](https://aihero.dev/skills-grilling) 在你选择候选项后遍历决策树。
* [domain-modeling](https://aihero.dev/skills-domain-modeling) 随着你做决策，保持 `GLOSSARY.md` 和 ADR 与时俱进。

其输出是一个构想，回流到主构建流程的 [grill-with-docs](https://aihero.dev/skills-grill-with-docs) 或 [to-spec](https://aihero.dev/skills-to-spec)。主流程末尾的对应技能是 [retro](https://aihero.dev/skills-retro)。本技能改进 Agent 工作的代码，而 `retro` 在构建后改进其周围环境（检查、标准、引导文件）。对于哪个技能适配某种情境，[ask-matt](https://aihero.dev/skills-ask-matt) 是整套技能的路由器。
