## 它做什么

`wizard` 生成一个交互式 bash 脚本，一步步引导人类完成手动流程：连接第三方服务、运行一次性迁移、将项目从状态 A 移动到状态 B。它会打开每个 URL，告诉你点击和复制什么，捕获返回的内容，并将其写入 `.env` 文件和 GitHub Actions 密钥中。

[agent](https://www.aihero.dev/ai-coding-dictionary/agent) 负责编写脚本；它从不运行。你在自己的机器上运行。因此，wizard 不是你遵循的指令列表；它是一个驱动流程并保存状态的程序，你的部分工作就是点击、粘贴并按 Enter 键。

## 何时使用它

你可以输入 `/wizard`，agent 也可以主动调用它。当它遇到你必须执行的一步（它无法生成的密钥、无法点击的仪表盘）时，它会为你构建一个 wizard，而不是将指令写入聊天中，因为那些指令会被滚走。

当挡在你面前的下一步是穿越仪表盘时，就使用它：

| 情况                  | wizard 会做什么                        |
| ------------------- | ---------------------------------- |
| 新开发人员需要在应用启动前配置六项服务 | 按顺序打开每个仪表盘，捕获密钥，并将它们写入 `.env`以及 CI |
| 一次性迁移需要按特定顺序拨动开关    | 将不可逆的步骤排列在确认门之后                    |
| 项目必须一次性从状态 A 移到状态 B | 引导转换过程，并报告它无法完成的部分                 |
| 你正打算把这些步骤写进 README  | 改而编写一个可执行版本，它无法悄无声息地腐坏。            |

不要用它来*决定*要构建什么；那是 [grill-with-docs](https://aihero.dev/skills-grill-with-docs) 和 [to-spec](https://aihero.dev/skills-to-spec) 的用武之地。

## 先决条件

生成一个不需要任何先决条件。它生成的 wizard 在 bash 上运行，当一个阶段设置 GitHub secret 或 variable 时会用到 `gh`。如果 `gh` 缺失或未认证，该阶段会变成警告，收尾摘要会告诉你需要手动设置什么，而不是让运行失败。

## 阶段

**阶段（stage）** 是在一个屏幕上完成的一项聚焦任务。脚本会在阶段之间清空终端，因此超出屏幕的阶段会丢失滚走的部分。你按依赖顺序编写阶段，并设置 `TOTAL_STAGES`，它驱动进度显示。

范围界定在写入任何一行之前进行。[skill](https://www.aihero.dev/ai-coding-dictionary/skill) 会读取仓库而不是冷启动询问：`.env*`、`docker-compose*`、框架配置，以及 `.github/workflows/` 中所有的 `secrets.*` / `vars.*` 引用：这些中的每一个都是 wizard 必须生成的值。然后它会向你展示有序的阶段列表以供确认，之后才将每个阶段映射到人类实际遵循的确切路径（"仪表盘 → 开发者 → API 密钥 → 显示测试密钥 → 复制"）。在不知道当前 UI 的情况下，它会询问你或查阅文档，而不是臆造点击操作。

对于每个捕获的值，范围界定决定它的去向：

| 去向                  | 何时                  |
| ------------------- | ------------------- |
| `.env`仅             | 本地开发需要它，CI 不需要      |
| GitHub secret       | CI 会读取它，且它是敏感的      |
| GitHub variable     | CI 会读取它，且它是公开的      |
| 同时写入 `.env`和 secret | 本地开发和 CI 都需要它       |
| 无处                  | 该阶段是一个纯动作：拨动开关、升级计划 |

## 模板已经解决了 UX 问题

[template](https://github.com/mattpocock/skills/blob/main/skills/engineering/wizard/template.sh) 自带完整体验：带剩余时间的进度、确认门、跨平台 URL 打开（包括 WSL）、密钥的隐藏输入、幂等的 `.env` upsert、`gh secret` / `gh variable` 写入，以及一份列出所有不得不跳过内容的收尾摘要。`STAGES` 标记以上的所有内容都是一个固定库，在每个 wizard 中都完全相同，也从不手工编辑。一致性正是关键。你的工作只是界定流程范围并编写各个阶段。

编写 wizard 的 agent 不会从头到尾运行它，因为它需要打开浏览器并等待人类输入。它通过静态验证代替：`bash -n`、尽可能使用 `shellcheck`，以及跟踪每个值都落在范围界定所说的位置，确保每个 `set_secret` 名称都与 CI 中真实的 `secrets.*` 引用匹配。相应地调整你的预期：第一次运行是给你的，而那次运行就是测试。

## 默认即临时

| 你拥有什么                 | 如何处理该脚本                                 |
| --------------------- | --------------------------------------- |
| 一次性迁移、个人设置、你永远不会重复的过渡 | 将它保存到一个临时目录或 `scripts/`路径下，运行它，然后删除     |
| 仓库中下一个人也会需要的设置路径      | 提交它并从 README 中链接它，这样他们运行脚本而不是重新询问 agent |

## 常见问题

**我的 API 密钥最终会进入模型的上下文（context）吗？**

不会。agent 编写脚本；它不运行脚本。你自己运行脚本，它会通过隐藏的终端输入捕获密钥，并直接写入 `.env` 或 `gh secret`。wizard 是一个 CLI，模型与它没有连接。有一点需要注意：这适用于 wizard 在运行时捕获的值。如果你在界定流程范围时把密钥粘贴到聊天中，它就会像任何其他粘贴的文本一样进入[上下文](https://www.aihero.dev/ai-coding-dictionary/context)。

**我能返回去修正输错的值吗？**

运行中途无法返回。没有后退按钮：阶段会向前运行，第三阶段答错意味着 Ctrl-C 并重新运行。重新运行在设计上是廉价的：任何已经写入 `.env` 的值都会作为默认值再次提供，因此你可以在答对的阶段按 Enter 跳过，只重新输入答错的那个。这在发布周被提到过，但一直没解决：“很喜欢！不过有一点，有没有办法返回并修正你输入的内容？”

还有一个相关的未决 bug。`ask` 提示中的方向键会插入 `^[[D` / `^[[C` 而不是移动光标，因为该提示使用 `read -r` 而不是 Readline（[issue #741](https://github.com/mattpocock/skills/issues/741)）。退格键有效；方向键无效。请删回到错误处，而不是把光标移进去。

**它知道我已完成什么设置吗？**

部分知道，且少于发布时的反应所假设的。它在询问之前会读取仓库（你的 `.env` 文件、`docker-compose`、框架配置、CI 中的 `secrets.*` 引用），所以它会将范围界定到真正缺失的值，而不是像 README 那样从零开始。它不做的是检查第三方服务。如果密钥存在于你的 `.env` 中，wizard 会将其回显并提供，按 Enter 保留；如果你已经创建了 Stripe 账户但从未保存密钥，wizard 仍会引导你去该仪表盘。

**它在 grill-with-docs 和 to-spec 之后的工作流中处于什么位置？**

并没有特定位置。它是一个独立的技能，不是链式步骤。常见的猜测是 `/grill-with-docs → /to-spec → /wizard`，这个顺序没问题，但触发点是出现了一个手动流程，这可以发生在任何时间点：开始之前、构建中途，或者是发布很久之后。它也作为一个发现工具发挥作用：范围界定会揭示任务的隐藏先决条件，比如你没想到的那三个 API 密钥，在你承诺工作之前。

**它在 Claude Code 之外也能用吗？**

该产物无条件可以工作：它是一个普通的 bash 脚本，不在乎是哪个 [harness](https://www.aihero.dev/ai-coding-dictionary/harness) 生成的。技能本身由模型调用，因此它列在到处：在 Claude Code 中输入 `/wizard` 或在 Codex 中输入 `$wizard`，或者只是描述你卡住的设置。由模型调用也使其远离 [#693](https://github.com/mattpocock/skills/issues/693)，在那里 Claude 的桌面和网页界面会从 [model](https://www.aihero.dev/ai-coding-dictionary/model) 列表中删除 *用户调用* 的技能，并将它们报告为未安装。

**它以前不是由用户调用的吗？**

以前是。现在它由模型调用，所以当 agent 遇到你必须执行的一步时，它会主动调用它。以前你能做的任何事情都没有停止工作：模型调用*增加了* agent 的触达范围，它从未移除你的，所以 `/wizard` 的行为和以前完全一样。改变的是它淘汰的失败模式：agent 在构建中途遇到凭据墙，然后向聊天中倾倒六个编号步骤供你手动执行。

**它以前位于 `in-progress/`它现在在哪里？**

`engineering/`，自 v1.2 起。它从 beta 分类中毕业，现在随插件一起发布，因此它会与其他正式发布的技能一同到达，而无需单独安装。它在毕业时行为没有变化。

## 如果它起作用了

* 在任何脚本存在之前，你会看到一个排序列表，以及每个阶段产生的值，并被要求确认。
* 每个 URL 都会先被打开，然后才会询问该页面的值。你永远不会被要求粘贴你没有被引导去获取的内容。
* 机密内容以盲输方式输入。不会有任何敏感内容回显到你的滚动历史中。
* 每个阶段都适配一屏。你仍然需要的内容不会滚出屏幕。
* Ctrl-C 后重新运行会从你上次中断的地方继续，并将已保存的值作为默认值提供。
* 最终屏幕会列出它写入的内容，并单独列出它无法完成、需要你手动完成的事项。

## 它在系统中的位置

`wizard` 是一个随时可用的独立技能，位于自动化停止而人类必须点击的那条线上。它最近的邻居是 [setup-matt-pocock-skills](https://aihero.dev/skills-setup-matt-pocock-skills)，因为两者都是为了将仓库置于可用状态：前者配置这组技能，而 `wizard` 为其他所有内容生成设置路径。它也与 [implement](https://aihero.dev/skills-implement) 配对：当构建中需要凭据或手动切换的功能时，wizard 是完成人类那部分工作的方式。当你不确定哪个技能适合此时，[ask-matt](https://aihero.dev/skills-ask-matt) 会为你指路。
