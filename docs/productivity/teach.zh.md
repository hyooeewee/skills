## 功能说明

`teach` 将您运行它的目录转换为一个持久的教学工作区，并在许多[会话](https://www.aihero.dev/ai-coding-dictionary/session)中教授您一个主题，简而言之，就是一系列独立的 HTML 课程。

它不会从 [模型](https://www.aihero.dev/ai-coding-dictionary/model) 已知的内容中教学。[参数化知识](https://www.aihero.dev/ai-coding-dictionary/parametric-knowledge) 被视为不可信：在开始教学之前，它会去寻找高可信度的资源，将它们记录在 `RESOURCES.md` 中，并在每一节课中引用它们。另一个结构性的事实是它是 [有状态的](https://www.aihero.dev/ai-coding-dictionary/stateful) —— 任务、资源、课程以及您所学内容的记录都以文件的形式存在于目录中，因此下一节课会从这些文件中接续，而不是从上次对话的残留内容中。

## 何时使用

您通过输入 `/teach` 来调用它 —— [代理](https://www.aihero.dev/ai-coding-dictionary/agent) 不会自动使用它。

当学习本身就是项目时使用它：一种语言、一个框架、一个您刚加入的代码库、瑜伽、着色器、一个认证。它不是用来进行一次性解释的工具。

| 您的需求                                                                                     | 选择                                                                       |
| ---------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| 希望跨越数周学习一个主题，并累积会话                                                                       | `teach`                                                                  |
| 在当前会话中解释一个想法                                                                             | 只需在该会话中提问                                                                |
| 由于上一次消息未能说服，代理重新介绍了它                                                                     | [wait-what](https://aihero.dev/skills-wait-what)                         |
| 为了深化您已有的思考，而不是获取新材料                                                                      | [grill-me](https://aihero.dev/skills-grill-me)                           |
| 一个后台代理来阅读 [一手来源](https://www.aihero.dev/ai-coding-dictionary/primary-source)并为您留下一个引用的文档 | [research](https://aihero.dev/skills-research)                           |
| 为了在学习过程中学习新内容，而不至于偏离 [grill-me](https://www.aihero.dev/ai-coding-dictionary/grilling)    | [handoff](https://aihero.dev/skills-handoff)转移到一个教学工作区，然后在那里 `teach`进行教学 |

## 前置条件

`teach` 构建的是目录而不是文件，且该技能假设每个工作区只有一个任务 —— 所以请在您愿意将其交给单一主题的地方运行它。将其与您正在工作的项目分开：单独的仓库是推荐的存放地，而不是全局的 `~/.learnings/` 文件夹或工作项目本身。专门的仓库也使得课程可以被提交，这正是团队共享它们的方式。

该目录中累积的内容：

| 路径                      | 包含内容                                                  |
| ----------------------- | ----------------------------------------------------- |
| `MISSION.md`            | 您学习此内容的理由。其他所有内容都以此为基础；如果它缺失，首先要做的是 `teach`会采访您，直到它不是 |
| `RESOURCES.md`          | 它教学所依据的经过验证的来源，分为知识和智慧（社区）                            |
| `lessons/*.html`        | 编号课程 —— 教学的主要单位                                       |
| `reference/*.html`      | 压缩的备忘单、算法、词汇表：您实际会查阅的文档                               |
| `learning-records/*.md` | 关于您有据可学内容的 ADR 风格笔记，用于决定下一步教学什么                       |
| `assets/*`              | 可重用组件 —— 首先是共享样式表 —— 这样课程看起来就像一个整体                    |
| `NOTES.md`              | 您声明的教学偏好                                              |

关于该列表的几点诚实说明。词汇表适合大多数主题，但该技能附带了一个 `GLOSSARY-FORMAT.md`，而 `SKILL.md` 不再链接它，所以您只有提出要求才能获得它 ([issue #559](https://github.com/mattpocock/skills/issues/559))。而且工作区并不总是创建在您期望的位置 —— 在其上构建长课程之前，请参阅下面的第一个问题。

## 存储强度，而非流利度

需要思考的词是 **存储强度**：长期记忆，与 **流利度** 相对，那种在阅读时感觉像掌握了一切，但一周后就会消失的即时回忆。`teach` 通过**令人愉悦的困难**来构建前者 —— 回忆练习、间隔重复、交叉学习。知识优先，此时困难是敌人，因为它会吞噬您理解它所需的**工作记忆**；然后技能通过紧密的反馈循环进行训练，此时困难是工具。

有两件事引导您被教授的内容。**任务** —— 您想要这个的具体现实原因 —— 为每节课奠定了基础；如果没有它，课程就会变得抽象，没有任何东西决定下一步。从任务和学习记录中，`teach` 在您的**最近发展区**内选择下一节课：具有足够的挑战性，需要付出努力，但又不会过于超前以至于无法学习。

这也是为什么该技能会拒绝，而不是顺从。一个需要 **智慧** —— 现实判断力 —— 的问题会得到一个尝试性的答案，然后指向一个您可以测试它的社区。测验是一扇门，而不是一种形式：一位用户报告说说了声'非常感谢'，然后被告知练习仍然有效。

## 课程、参考资料和组件

**课程**是一个独立的 HTML 文件，短到可以在一次会话中完成，与任务挂钩，提供一次实实在在的胜利。它引用了来源，并推荐一个原始资料供您自己去阅读，并链接到兄弟课程和参考文档。

值得了解的划分：课程很少被重新审视，参考文档则不然。所以课程的压缩精髓 —— 语法表、算法、姿势序列、词汇表 —— 属于 `reference/`，而不是埋在介绍它的课程里。

课程是由 `assets/` 中的**组件**构建的：样式表、测验小部件、模拟器、图表辅助工具。复用是默认设置。代理在编写课程之前读取 `assets/` 并基于现有的内容进行构建，任何第二节课可能用到的任何新内容都作为组件编写，而不是内联。共享样式表是每个工作区获得的第一个组件；它阻止了输出变成一堆一次性作品。

## 常见问题

**它把文件放在哪里？我的文件最终出现在了 `~/.claude/skills` 中。** 一个真实存在的公开漏洞 ([#377](https://github.com/mattpocock/skills/issues/377))。`SKILL.md` 同时对两个不同的根目录使用 `./`：`./MISSION-FORMAT.md` 和它的兄弟文件确实位于已安装技能中的 `SKILL.md` 旁边，而 `./lessons/`、`./reference/`、`./learning-records/` 和 `./assets/` 应该位于您的目录中。一个将第一种情况解析为技能安装目录的代理会继续在那里解析第二种情况，并将您的课程写入技能文件夹。在构建之前，检查第一节课落在哪里，并在开始时明确命名目录，而不是依赖对'当前目录'的理解。

**我应该停留在同一个会话中，还是每节课开始一个新的会话？** 这三种方法都有效 —— 停留在同一个会话中，在新会话中重新调用 `/teach`，或在同一个文件夹中打开新会话。每节课都是一次独立的调用。文件夹是连续性，而不是对话。常见做法是在工作区中打开一个新会话并说 `/teach next lesson for <topic>`。

**我如何知道它没有教我一些它编造的东西？** 仅凭技能的说法您无法确定。您阅读原始资料。`teach` 还不够可靠，不能盲目信任，任何基于 LLM 构建的技能都不行。基础机制 —— `RESOURCES.md`、每节课中的引用、每节课推荐一个原始资料 —— 存在的目的不是为了消除验证的需求，而是为了让验证变得廉价。失败并非假设：一位学习 2x2 魔方（魔方）的用户收到了伪造的移动序列，这些序列无法解决它。针对这种情况的诊断清单是模型、工具、努力 —— 以及来源是什么。在具有精确记号的程序化领域，风险最高；而在输出可以立即验证的领域，风险最低，例如您可以运行的代码。

**测验的正确答案总是第一个选项。**
这在多个用户（使用 Sonnet、Opus 和 GLM）身上得到确认，但问题仍未修复。`SKILL.md` 现在要求每个答案的单词数量相同，这消灭了另一个线索 —— 以前正确的答案总是唯一一个经过完整推理的 —— 但并没有涉及位置。一位贡献者测试了针对位置的指令级修复，并在九节课中报告正确答案仍然出现在 A 位的次数为 33/33 ([#335](https://github.com/mattpocock/skills/issues/335))，这指向了 `assets/` 中的一个洗牌测验组件才是真正的修复方案，而不是更好的措辞。在此之前，请将答案位置视为无意义。您的 `assets/` 目录由您掌控，因此请求一个在渲染时进行洗牌的组件是一个合理的本地修复方案。

**它假定我已经知道了某些东西，并使用了它从未定义的术语。**
这是最常见的实质性投诉。没有评估步骤：`teach` 根据任务和学习记录推断您的水平，而在第一节课中并没有学习记录。一位在 wayfinder 流水线中运行它的用户直言不讳地说 —— “它从未进行过评估以确定我的起点，所以它对我已经知道的事情做出了大量假设。” 另一位用户报告说课程依赖于未定义的行话，以及一节针对其硬件量身定制的课程，该课程涵盖了硬件能做什么，却从未说它不能做什么。有两件事有帮助：在第一条消息中说明您先前的知识和您的知识缺口，并在课程讲错时大声纠正级别，因为这种纠正会成为学习记录并引导下一节课。明确的知识评估步骤是一个持续的功能请求 ([#725](https://github.com/mattpocock/skills/issues/725))，而非已实现的行为。

**它是否进行间隔重复，以及它知道何时停止教学？**
第一个是否定的，第二个也并不可靠。间隔重复和交叉学习是课程设计所遵循的原则，但没有安排复习，也没有 Anki 或日历集成 —— 两者都是重复出现的请求。相关的差距在于退出标准：正如一位用户所说，`teach` “很擅长生成下一节课，但不太擅长知道何时停止并切换到复习或实际练习。” 如果您希望进行复习或操练而不是新材料，请提出要求；该技能不会自行建议切换。

**它是否仅对代码有用？**
不是，且非编程用途占记录的更大一部分：韩语、日语正式语体、钢琴、吉他、棋盘游戏设计、OpenSCAD、电影情节、Azure 和 CCNA 认证、大学考试，以及八岁和十岁的孩子获得关于密室逃脱和火蝾螈的可打印书籍。该技能中没有编程特定内容 —— 任务、资源、最近发展区和操练工作在任何领域都是一样的。在代码方面，报告的最强用途不是从头学习一门语言，而是在一个不熟悉的代码库或新团队的栈中找到方向。

**我应该用哪个模型运行它？**
没有标准答案，报告的差异也很大。据报道，比中等设置更高的 [推理努力](https://www.aihero.dev/ai-coding-dictionary/effort) 能产生明显更好的课程。一位用户通过 Copilot CLI 使用 Codex 运行了相同的技能，得到一个 30 行的 HTML 卡片，而 Claude Code 生成的是完整的课程。它在 Claude Cowork 中无修改运行，取决于您的组织是否允许在那里添加技能。如果课程内容显得单薄，请在重写提示词之前更改模型、[工具](https://www.aihero.dev/ai-coding-dictionary/harness) 或努力程度。

## 判断是否生效

* 在一个空目录中，它做的第一件事是询问你想要这个的原因，而不是直接生成课程。
* `RESOURCES.md` 在课程完成之前就会填满，并且每节课都会列出一个值得您亲自阅读的主要来源。
* 课程中的陈述都会附有链接。没有引用的课程意味着该技能仅凭记忆在授课。
* 一节课需要你专注投入，并能让你学会做一件你以前做不到的事情。
* 在文件夹中打开一个新会话并说“下一课”，会继续课程而不是重新开始。
* `learning-records/` 会增长，课程会停止重复教授您已经证明掌握的内容。
* 课程看起来像一门连贯的课程 —— 它们链接 `assets/` 中的样式表，而不是每节课都自带一个。
* 对于需要判断的问题，它会指引你去论坛、Reddit 子版块或课堂，而不仅仅是给出一个答案。

## 在系统中的位置

`teach` 是一个 **随时可用的独立工具**。它不是构建链中的一个步骤，也与工程流程不共享工件；它拥有自己的目录，并在主题持续的时间内驻留在那里。

它唯一的真正邻居是 [handoff](https://aihero.dev/skills-handoff)，这是 Matt 命名为“如果有人盘问我我不懂的事情，我该怎么做？”的答案：不要停下来去学习 —— 使用 `/handoff` 进入教学工作区，在那里用 `/teach` 学习，然后回去继续之前的工作。附近的替代方案是 [research](https://aihero.dev/skills-research)，当你需要的是引用文档而不是课程和复习时，它就是那个。当你不确定哪个技能或流程适合时，[ask-matt](https://aihero.dev/skills-ask-matt) 会引导你浏览整套技能。
