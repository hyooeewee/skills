## 功能说明

`handoff` 将当前对话压缩成一个 **交接文档**——一个 markdown 文件，写入操作系统的临时目录而非工作区，以便新的 [agent](https://www.aihero.dev/ai-coding-dictionary/agent) 可以读取它以接手工作。

它带来的是 **可移植性**，而非压缩。这让该技能比听起来更专一。只有当工作必须 *旅行* 时——去新的 [harness](https://www.aihero.dev/ai-coding-dictionary/harness)、新的目录、同事，或者你想分叉的侧边任务——你才需要一个文件。如果没有东西在旅行，你不需要交接：留在 [session](https://www.aihero.dev/ai-coding-dictionary/session) 中，使用 `/clear`、[subagent](https://www.aihero.dev/ai-coding-dictionary/subagent) 和 `/compact` 可以覆盖普通的阶段结束情况，而且 `/compact` 比这个技能更频繁地覆盖这种情况。

## 何时使用

你通过输入 `/handoff` 来调用此功能——agent 不会自动使用它。传递一个备注说明下一个会话的用途，然后就会为它生成文档。

四种情况构成了全部触发条件：

| 情况                    | 为什么需要文件                                                               |
| --------------------- | --------------------------------------------------------------------- |
| 交换框架 — Claude → Codex | 新的框架无法看到旧的 [上下文](https://www.aihero.dev/ai-coding-dictionary/context) |
| 移动到不同的目录或仓库           | 原型目录是常见情况                                                             |
| 将工作发送给同事              | 他们需要一些可以阅读的东西                                                         |
| 在阶段中途分叉一个侧边任务         | 你继续工作；第二个 agent 接管分叉任务                                                |

对于其他情况——相同的框架、相同的目录，你完成了 [grilling](https://www.aihero.dev/ai-coding-dictionary/grilling) 并准备进入实现阶段——`/compact` 是正确的选择。[ask-matt](https://aihero.dev/skills-ask-matt) 在阶段边界处承载了排序后的树，涵盖了所有五个选项。

## 分支是人们跳过的用法

技能的描述读起来像会话恢复：写一个摘要，结束在这里，在那里继续。那样读的话，它看起来比 `/compact` 差，所以被略过了。分叉的情况是值得知道的。你 **留在你的会话中**，并将累积的上下文副本交给正在并行工作的第二个 agent。

这就是通过 [prototype](https://aihero.dev/skills-prototype) 的迂回所做的事情。你正深入在设计对话中，你遇到了一个只有运行代码才能解决的问题，你不想在你构建的对话线程上浪费时间去弄清楚。交接到一个原型会话，得到答案，把答案交回去，并在原始线程中引用它。两次跨越，一次实时对话，无需重新解释。

阶段边界处的五个选项中有三个保留了不同的东西：`/compact` 保留你的意图，`/clear` 什么都不保留，`/handoff` 保留工作的可移动能力。

## 什么被携带，什么没有

文档携带实时线程——正在进行的、原因以及下一步——加上一个 **建议技能** 部分，命名下一个 agent 应该使用什么。在写入之前会删减机密信息。

它故意不携带任何已经写下来的东西。规格说明、计划、ADR、问题、提交和差异是通过路径或 URL 引用的，而不是被复制。这保持了文件的大小，并且它将已确定的细节保持在一个地方，而不是两个漂移的地方。

## 常见问题

**交接还是压缩？** 除非有东西在旅行，否则使用 `/compact`。继续同一任务是压缩，而不是交接——相同的框架、相同的目录，并且你需要保持同步，这是阶段边界树在大多数日子里落脚的地方。`/handoff` 的优势不在于它总结得更好；而在于结果是你可以带到 `/compact` 无法到达的地方的一个文件。

**那么 compact、clear 和 handoff 之间的实际区别是什么？** 保留了三种不同的东西。`/compact` 压缩此上下文并让你在新的窗口中继续——意图得以保留。`/clear` 清空窗口并从零开始——当你身后的一切都是可丢弃的时候是正确的，如果不可丢弃则是单向的。`/handoff` 写入一个可移植的文件——工作在移动到其他地方后幸存下来。注意，这三者都将 **[主要来源](https://www.aihero.dev/ai-coding-dictionary/primary-source)**（发生的对话）转换为 **[次要来源](https://www.aihero.dev/ai-coding-dictionary/secondary-source)**（它的摘要）。继续是唯一没有这样做的操作，这就是为什么它是首先被排除的那个。

**我的交接文件去哪了？** 临时目录，这是该技能报告最多的摩擦点：路径很长，它们因操作系统而异，而且在 Windows 上 agent 有时需要尝试多次才能找到正确的那个。要求返回路径并在继续之前保留它。临时目录是故意的：交接是一个过境文档，而不是你维护的工件。它也不是一个持久的——请看下一个问题。

**我的交接文件在会话之间消失了。** 有些环境会在会话之间清除临时文件——Codex 是报告的案例——而且 `/private/tmp` 在重启后会消失。如果下一个会话在一小时内没有启动，或者在不同的框架下启动，请在文件写入后立即将其复制到某个持久的地方。这同样适用于文档*指向*的任何东西：引用临时文件中其他文件的指令是下一个 agent 无法跟随的。

**我实际上如何把它交给下一个 agent？** 打开新会话并将其指向路径：读取此文件，然后继续。指向文件而不是将摘要粘贴到 shell 命令中——包含反引号或 `$(...)` 的摘要在被插入到 `claude "<summary>"` 中时会被破坏，通常的失败是静默截断而不是错误，所以新 agent 以一个安静的未完成简报开始。

**这与 `/branch`、`--fork-session` 或内置的 `/handoff` 相同吗？** 类似，但不完全相同，而且 `/branch` 不是这里发布的技能——`/handoff` 是规范名称。分叉继承上下文的精确副本；这个技能在文件中产生针对已陈述的下一个任务的*有针对性的*压缩。分叉能做到的地方——相同的机器、相同的框架、相同的目录——分叉的工作量更少。当目的地是分叉无法到达的地方时，文件获胜。

**什么时候某样东西应该属于 `CLAUDE.md` 而不是这里？** 问问自己下个月它是否仍然为真。`CLAUDE.md` 是关于项目的静态上下文，加载到每个会话中，无论是否相关。交接是关于正在进行的某项工作的，一旦该工作落地就结束了。不断被重新解释的事实是 `CLAUDE.md` 的问题；未完成的任务是一个交接。

**它捕获的是“是什么”，而不是“为什么”。** 一个公平且反复出现的批评。两件事有帮助。传递论点——告诉它下一个会话是为了什么——这样关于*那个*的推理被保留而不是被简化。还要注意会话从未真正验证过的自信主张：“X 还没构建”，“Y 已完成”。下一个 agent 将文档视为合同，不会重新检查它，因此写成事实的信念变成了后面所有内容的错误前提。在移交文档之前阅读它，并降级任何你只是假设的东西。

**为什么它是一个技能而不是斜杠命令？** 两者都有效；它们适合不同的情况。作为一个技能，它通过与其他所有内容相同的安装路径发布和更新，这就是它可共享的原因——agent 不会自行触发它的约束是由其前置元数据设置的，而不是由机制设置的。

## 判断是否生效

* 文档是对话的一小部分，规格说明、问题和差异在其中以路径和 URL 的形式出现，而不是作为复制的文本。
* 你可以冷读它，而不需要打开原始会话，并知道下一步做什么。
* 新的 agent 开始工作而不是要求你重新解释设置。
* 在分叉的情况下，当你回到它时，你的原始会话仍然静静地坐在那里没有被触碰。
* 建议技能部分命名了你本会自己获取的技能。
* 其中没有任何东西是密钥、令牌或密码。

## 在系统中的位置

`handoff` 是一个 **随时可用的独立技能**，它生活在会话之间而不是构建链内部——但这是一个狭窄的技能，诚实的地图是，你使用它的频率会比阶段边界处的其他四个选项低。它最近的邻居是 [prototype](https://aihero.dev/skills-prototype)，因为原型生活在它自己的目录中，往返是正好这个技能所跨越的。当你处于边界且不确定是继续、清除、交接、委托还是压缩时，[ask-matt](https://aihero.dev/skills-ask-matt) 承载了排序这五个选项的树——并将你引导到集合的其余部分。
