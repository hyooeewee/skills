## 它做什么

`grilling` 是一种面试循环，它会在任何人采取行动之前，对计划、决策或想法进行压力测试。它将主题映射为一棵**设计树**：每个决策都会分支出依赖它的决策，并逐个分支地对你进行面试，直到没有任何假设保持未被陈述。

它不会一次问一个问题，也不会一次问完所有问题。每一**轮**都会询问整个**前沿**：即所有前提条件已经确定的决策，除此之外别无其他。如果一个问题依赖于另一个问题，它们绝不会出现在同一轮中；一个取决于尚未确定答案的问题属于后续轮次。你的回答会确定决策，前沿向外推进，下一轮会询问那些被打通的问题。通常情况下，13 个问题会分布在约 3 轮中，而不是 13 轮。

## 何时使用它

输入 `/grilling`，或者当任务匹配时，[agent](https://www.aihero.dev/ai-coding-dictionary/agent) 会自行调用它。它是 grilling 系列中唯一一个由模型调用的 [skill](https://www.aihero.dev/ai-coding-dictionary/skill)，所以你很少直接输入它。通常是你输入的某个技能在为你运行它。

直接输入 `/grilling` 只会得到普通的访谈，没有其他内容。当你需要更多时：

## 轮次、前沿，以及由谁决定

该技能基于三个核心概念。

**设计树**是主题的模型：决策挂载着决策。**前沿**是所有前提条件均已确定的决策集合：即代理当前能够提出的唯一问题集合。一**轮**就是一个前沿，完整提问并完整作答。

在一轮中，每个问题都有固定格式：编号和标题位于 `❓` 之后，然后是正文，最后是代理推荐的答案单独放在一行 `➡️` 后。这种格式让你可以按编号回答一轮问题（例如"1 yes, 2 the second option, 3 no, here's why"），而不必逐字引用问题。该格式有一个已知问题。推荐答案有时会反驳问题本身的措辞，因此同意推荐答案意味着对问题回答"否"。遇到这种情况时，请回答推荐答案并说明情况。

设计的另一半是事实与决策的分离。事实是技能自己的工作。当前沿问题需要某些 [环境](https://www.aihero.dev/ai-coding-dictionary/environment) 可以确定的信息时，代理会派遣 [子代理](https://www.aihero.dev/ai-coding-dictionary/subagent) 去查明，而不是问你。该轮不等待该研究完成；只有依赖该研究的问题才等待。决策由你做出，代理必须等待。运行 `grilling` 却自行回答决策的代理就破坏了该技能。当前沿为空时会话结束。代理随后会等待你确认双方理解一致，然后才根据你们达成的共识采取行动。

前沿有一个限制。代理凭判断选择它，而不是从图中计算出来。因此它可能把两个问题放在同一轮，事后才发现其中一个答案本该改变另一个问题。唯一的防范是告诉它。这会在下一轮重新打开受影响的分支。

## 常见问题

**我可以回到一次只问一个问题吗？**
可以，而且很大一部分用户都是这样做的。请将以下内容添加到你的全局 `CLAUDE.md`：

```
When grilling, ask one question at a time.
```

并非所有人都偏好基于轮次的默认方式。阅读较慢的用户、使用第二语言工作的用户，或利用顺序格式帮助聚焦的用户，反馈一次一个问题对他们更有效。这种选择退出是受支持的设置，而非变通方法。

`/batch-grill-me` 去哪了？进入这个技能。基于轮次的提问曾作为单独的技能短暂发布，然后移入了 `grilling` 本身，因此所有基于原语（`grill-me`、`grill-with-docs`、`triage`、`wayfinder`）构建的东西都立刻获得了它。没有 `batch-grill-me` 可安装，也没有单独的顺序技能；上面的 `CLAUDE.md` 行是回到一次一个问题的途径。

**一次问完整轮，难道不会丢失我先前答案本会引出的问题吗？**
这是对轮次最常见的反对意见，而前沿机制对此给出了答案。一轮只包含相互不依赖的问题，因此轮内的任何答案都无法使同一轮内的另一个问题失效。你的回答仍然会改变后续内容，因为代理会从头计算每一轮。你确实会失去一些东西，但比"一次性问完所有问题"暗示的要少。见上文前沿的限制。

**问题问完了就开始构建。**
确认关卡正是为此而存在。只有当你说理解已共享时，技能才算结束，而不是前沿为空时。较弱且更快的 [models](https://www.aihero.dev/ai-coding-dictionary/model) 仍会跳过关卡。用户最常在低努力或非前沿模型上遇到此情况，它们将"面谈直到达成共识"压缩成几个问题和一个大纲。如果你的模型这样，可靠的修复是在你自己的 `AGENTS.md` 或 `CLAUDE.md` 中加一行，告诉代理未经许可不得实现。

**它自己回答了自己的问题，而不是问我。**
这是一次运行中的 bug，也是技能文本将事实与决策分离的原因。最常发生在另一个技能运行 `grilling` 以解决工单时，代理把该任务视为继续推进的许可。同一约束也是没有异步模式的原因。有人要求一个变体：读取 GitHub issue 并发布一份合并的决策备忘录，那是另一个技能，因为无人作答的 grilling 会话产出的是代理的意见，而非你的。

**我能限制问题数量吗？**
不能，刻意不在范围内。有的计划只需三个问题，有的需要五十个；固定上限要么截断困难情况，要么在简单情况下显得武断。预期的控制方式是自然语言。告诉它收尾，或停下来接受现状。如果会话运行很久，通常是因为范围太大；拆分工作，分别 grilling。

**我只安装了 `grill-me`，但什么也没有发生。**
`grill-me` 是一个只有一行的技能，其全部内容就是"运行一次 `/grilling` 会话"，所以它也需要安装这个技能。`grill-with-docs` 也是如此，它另外还需要 [domain-modeling](https://aihero.dev/skills-domain-modeling)。安装全套可以避免这个问题；有选择地安装则意味着也需要安装原语。

**`grill-with-docs` 运行了，但从未加载 `grilling`。**
这是一个真实的 bug，仍未修复，用户在各种 [harnesses](https://www.aihero.dev/ai-coding-dictionary/harness) 和模型上都报告过。一个技能引用另一个技能并不能可靠地导致后者加载，而 `grill-with-docs` 引用了两个。标志是会话一次性问完所有问题且没有推荐答案。这意味着模型在即兴面试，而不是运行本技能。直接问代理是否加载了 `grilling` 和 `domain-modeling` 通常能恢复。

## 如果它起作用了

* 一轮以编号列表的形式呈现，每个问题及其建议分别放在独立的 `➡️` 行中，你可以按编号回答整轮。
* 一轮中的任何问题都不需要同一轮中的另一个问题先被回答。
* 后续轮次会问第一轮无法问出的问题。
* 它会去查找事实（读取文件、派遣子代理），而不是问你它本可以查明的事情。
* 后台运行的研究不会让当前轮次停滞；只有依赖它的那些问题才需要等待。
* 它会在最后停下来，请你确认双方理解一致，而不是直接开始工作。
* 问题数量保持在高位，而轮次数量保持在低位。

## 它在系统中的位置

`grilling` 是一个**原语**，而不是你安排的一个步骤：它是访谈技巧的单一事实来源，放在一个地方，这样每个需要访谈的技能都会使用它，而不是自行发明。[grill-me](https://aihero.dev/skills-grill-me) 和 [grill-with-docs](https://aihero.dev/skills-grill-with-docs) 是它的两个用户调用入口，`grill-with-docs` 是主构建链开始的地方，位于 [to-spec](https://aihero.dev/skills-to-spec) 之前。[wayfinder](https://aihero.dev/skills-wayfinder) 运行它来解决决策单，[triage](https://aihero.dev/skills-triage) 用来把一个含糊的报告“拷问”成可操作的报告，而 [improve-codebase-architecture](https://aihero.dev/skills-improve-codebase-architecture) 则在你选定一个候选方案深入后遍历树。当你不确定哪个入口合适时，[ask-matt](https://aihero.dev/skills-ask-matt) 会为你路由。
