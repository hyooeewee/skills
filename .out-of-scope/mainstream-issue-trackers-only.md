# 问题跟踪器集成仅限于主流工具

`setup-matt-pocock-skills` 仅对**主流**问题跟踪器提供一流支持。为小众、新兴或单一供应商的实验性跟踪器添加支持的请求不在范围内。

## 为什么这不在范围内

每个问题跟踪器后端都会将 CLI 形状（命令、标志、输出解析）硬编码到技能中。每个新的后端都需要持续维护，因为它必须随着工具 CLI 的演进而保持正常运行，并持续接受 `/to-spec`、`/to-tickets`、`/triage` 等的测试。只有对于用户实际拥有的跟踪器，才值得投入这种成本。

“主流”是一种判断，而非数字标准：

* GitHub、GitLab 和 Backlog.md 属于我们认为的主流工具：广为人知、广泛使用，且早已过了实验阶段。
* 一个全新的、以代理为中心、在 GitHub 上只有几百颗星的工具则不算，无论其设计多么有趣。

星标数、存在时间和下载量是做出判断时有用的信号，但都不是标准。标准是：一个典型的工程师会认出这个工具，并且很可能为他们的团队选择它吗？

针对非主流跟踪器的备用方案已经存在：

* `local markdown` 用于轻量级的仓库内跟踪。
* `other/custom` 供想要自行配置的用户使用。

这两者都不需要核心技能了解具体工具。
