# 向导

**向导**是一个 bash 脚本，它一步一步地引导人类完成一个手动流程，这个过程用手做很繁琐，每次都要向 AI 重新解释也很繁琐。它会打开每个 URL，准确地说出要点击和复制的内容，捕获这些值，将它们写到该去的地方（`.env`、GitHub secrets），在每个阶段进行确认，并显示还剩多少阶段。它可能配置第三方服务、运行一次性迁移，或将项目从一种状态移到另一种状态。

[template.sh](template.sh) 已经解决了令人愉悦的用户体验——逐步进度、确认门、跨平台 URL 打开（包括 WSL）、隐藏密钥输入、幂等的 `.env` 更新、`gh secret`/`gh variable` 写入，以及收尾总结。**你的工作只是界定流程并编写其阶段。** `STAGES` 标记上方的库在每个向导中都是相同的；这种一致性才是关键——永远不要手工编辑它。

向导默认是短暂的——为一次运行而构建，保存到临时目录或 `scripts/` 路径，任务完成后删除。只有当用户想要一个可重复的设置路径并希望它存在于仓库中时，才提交它。

## 流程

### 1. 界定流程

想出人类必须采取的每一个手动步骤以及沿途捕获的每一个值。先阅读仓库——不要在没有上下文的情况下提问：

* 对于设置：`.env`、`.env.example`、`.env.*`、`README`、`docker-compose*`、框架配置以及 `.github/workflows/*`（每一个 `secrets.*` / `vars.*` 引用都是向导必须产生的值）。
* 对于迁移或转换：当前状态、目标状态以及它们之间的不可逆操作。

然后向用户显示按顺序排列的阶段列表以及每个阶段产生的值，并确认——他们可能会添加、删除或重新排序。

**完成条件：** 每个阶段都已按顺序命名，并且对于每个捕获的值，你知道（a）人类从哪里获取它，（b）它写入的位置（`.env`、GitHub 密钥、两者或无处——某些阶段是纯动作），以及（c）它是否是密钥（隐藏输入）还是公开的。

### 2. 映射每个阶段的旅程

对于每个阶段，写出人类遵循的确切路径：打开哪个 URL、在那里做什么、值显示在哪里、它填充哪个变量——例如“仪表板 → 开发者 → API 密钥 → 显示测试密钥 → 复制”。如果你实际上不知道当前的 UI 或确切的命令，请说明并询问用户或查阅文档——绝不要编造可能不存在的步骤。

**完成条件：** 每个阶段都指向一个陌生人可以遵循的具体说明。

### 3. 编写向导

将 `template.sh` 复制到目标路径。按依赖顺序，用每个步骤的一个 `stage` 替换示例阶段。使用库辅助函数——`stage`、`say`/`step`、`open_url`、`ask`/`ask_secret`、`write_env`、`set_secret`/`set_var`、`pause`/`confirm`——并将 `TOTAL_STAGES` 设置为您编写的阶段数量。

遵守模板设定的标准：在询问其值之前打开 URL，对任何密钥使用 `ask_secret`，将每个持久化值写入 `write_env`，仅将 CI 实际需要的值写入 `set_secret`，并在任何不可逆操作之前使用 `confirm`。每个 `stage` 都会清除屏幕，以便只显示当前步骤——保持一个阶段专注于一个任务，这样人类需要的东西就不会滚出屏幕。不要触碰标记上方的库。

### 4. 验证和移交

* `bash -n <script>`；如果可用，运行 `shellcheck`。
* `chmod +x <script>`。
* 不要自己端到端运行它——它会打开浏览器并在等待人类输入时阻塞。改为静态跟踪它：步骤 1 中的每个值都被捕获并落在步骤 1 所说的位置，并且每个 `set_secret` 名称都与 CI 中的 `secrets.*` 引用完全匹配。
* 告诉用户如何运行它。如果这是一个可重复的设置路径，请提交它并从 README 链接它，以便下一个人运行脚本而不是问 AI。
