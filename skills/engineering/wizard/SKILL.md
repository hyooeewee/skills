# 向导

**向导**是一个 bash 脚本，它逐步引导人类完成一个手动流程，这个流程手工操作很繁琐，每次都要向 AI 重新解释也很麻烦。它会打开每个 URL，精确说明要点击和复制什么，捕获这些值，将它们写入所属位置（`.env`、GitHub 机密），在每个阶段进行确认，并显示还剩多少阶段。它可能用于配置第三方服务、运行一次性迁移，或将项目从一种状态迁移到另一种状态。

令人愉悦的用户体验已经由 [template.sh](template.sh) 解决：分阶段进度、确认门禁、跨平台 URL 打开（包括 WSL）、隐藏的机密输入、幂等的 `.env` 插入更新、`gh secret`/`gh variable` 写入以及最后的摘要。**你的工作仅仅是界定流程的范围并编写其阶段。** `STAGES` 标记上方的库在每个向导中都是相同的；这种一致性就是目的所在：永远不要手动编辑它。

向导默认是短暂的：为一次运行而构建，保存到临时目录或 `scripts/` 路径，任务完成后删除。只有当用户想要一个可重复的设置路径且该路径应该保留在仓库中时，才提交它。

## 流程

### 1. 划定流程范围

想出人类必须采取的每一个手动步骤以及沿途捕获的每一个值。先了解仓库，不要凭空询问：

* 对于设置：`.env`、`.env.example`、`.env.*`、`README`、`docker-compose*`、框架配置以及 `.github/workflows/*`（每个 `secrets.*` / `vars.*` 引用都是向导必须产出的值）。
* 对于迁移或转换：当前状态、目标状态以及两者之间不可逆的操作。

然后向用户展示按顺序排列的阶段列表以及每个阶段产生的值，并请确认：他们可以添加、删除或重新排序。

**完成标准：** 每个阶段都已按顺序命名，并且对于每个捕获的值，你知道（a）人类从哪里获取它，（b）它被写入哪里（`.env`、GitHub 机密、两者，或者无处写入；有些阶段只是纯操作），以及（c）它是机密（隐藏输入）还是公开的。

### 2. 规划每个阶段的操作路径

对于每个阶段，写出人类遵循的确切路径：要打开哪个 URL，在那里做什么，在哪里显示值，它填充哪个变量：例如“仪表板 -> 开发者 -> API 密钥 -> 展示测试密钥 -> 复制”。如果你实际上不知道当前的 UI 或确切的命令，就说明这一点并询问用户或查阅文档：永远不要编造可能不存在的步骤。

**完成标准：** 每个阶段都能追溯到陌生人可以遵循的具体说明。

### 3. 编写向导

将 `template.sh` 复制到目标路径。用每个步骤对应的一个 `stage` 替换示例阶段，按依赖顺序排列。使用库辅助函数：`stage`、`say`/`step`、`open_url`、`ask`/`ask_secret`、`write_env`、`set_secret`/`set_var`、`pause`/`confirm`。将 `TOTAL_STAGES` 设置为你编写的阶段数量。

保持模板设定的标准：在请求其值之前打开 URL，对任何机密内容使用 `ask_secret`，为每个持久化的值使用 `write_env`，只为 CI 实际需要的值使用 `set_secret`，并在任何不可逆操作之前使用 `confirm`。每个 `stage` 都会清屏，以便只显示当前步骤：保持每个阶段专注于一项任务，这样人类需要的任何内容都不会滚出屏幕。不要触碰标记上方的库。

### 4. 验证并交接

* 运行 `bash -n <script>`；如果可用则运行 `shellcheck`。
* 运行 `chmod +x <script>`。
* 不要自己端到端运行它：它会打开浏览器并在等待人类输入时阻塞。相反，静态地跟踪它：步骤 1 中的每个值都被捕获并落入步骤 1 所指定的位置，并且每个 `set_secret` 名称都精确匹配 CI 中的 `secrets.*` 引用。
* 告诉用户如何运行它。如果这是一个可重复的设置路径，请提交它并从 README 链接它，这样下一个人就直接运行脚本，而不是询问 AI。
