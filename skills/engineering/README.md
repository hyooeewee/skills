# 工程

我日常处理代码工作所用的技能。

## 用户调用

仅在您输入它们时才可访问（Claude Code：`disable-model-invocation: true`；Codex：`agents/openai.yaml` 中的 `policy.allow_implicit_invocation: false`）。

* 询问哪种技能或流程适合您的情况。这是本仓库中用户调用技能的路由器。
* 一场烧烤会话（Grilling session），同时构建项目的领域模型，精炼术语并内联更新 `CONTEXT.md` 和 ADRs。
* 通过角色状态机处理问题。
* 扫描代码库以发现改进机会，将其呈现为可视化的 HTML 报告，然后针对您选择的任意一个进行烧烤会话。
* 为工程技能配置此仓库（问题追踪器、分类标签、领域文档布局）。每个仓库只需运行一次。
* 将当前对话转化为规范并发布到问题追踪器。
* 将任何计划、规范或对话分解为一组追踪子弹（tracer-bullet）票据，每个票据声明其阻塞关系（blocking edges），可以是本地文件中的文本，也可以是真实追踪器上的原生阻塞链接。
* 构建规范或一组票据所描述的工作，在预商定的接合点（seams）处执行 `/tdd`，并在提交前通过 `/code-review` 完成收尾。
* 将大量工作（超过一个代理会话能处理的量）规划为问题追踪器上决策票据的共享地图，逐个解决，直到通往目的地的路径清晰为止。

## 模型调用

模型或用户均可访问（采用丰富的触发措辞，便于模型主动调用）。

* 构建一个一次性原型来回答设计问题：一个用于状态/逻辑的可共享 HTML 文件，或者几个可切换的 UI 变体。

* 针对顽固 Bug 和性能回归的纪律性诊断循环：构建一个针对此 Bug 变红的反馈循环 → 最小化 → 假设 → 仪器化 → 修复 → 回归测试。

* 针对高信任度的原始资料调查问题，并将发现结果作为仓库中引用的 Markdown 文件保存，作为后台代理运行。

* 采用红-绿-重构循环的测试驱动开发。一次构建一个垂直切片（vertical slice）的功能或修复一个 Bug。

* 通过挑战术语、用场景进行压力测试以及内联更新 `CONTEXT.md` 和 ADRs，主动构建和精炼项目的领域模型。

* 设计深度模块的共享纪律和词汇：小接口、清晰的接合点（seams）、通过接口可测试。

* 对自固定点以来的差异进行双轴审查：**标准**（是否遵循仓库的编码标准，以及 Fowler 嗅觉基线？）和**规范**（是否忠实地实现原始问题/规范？），作为并行子代理运行。

* 逐块处理进行中的 git 合并或变基冲突，通过追溯到每方原始来源的意图来解决，然后完成操作，绝不 `--abort`。

* 生成一个交互式 bash 向导，引导人类完成只有他们能执行的步骤：配置基础设施、设置凭据或 CI 密钥、浏览不熟悉的三方仪表板，或运行一次性迁移或切换。
