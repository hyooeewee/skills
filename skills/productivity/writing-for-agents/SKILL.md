为智能体消费的任何文档编写提供参考——技能、`AGENTS.md` / `CLAUDE.md`、通过指针到达的文档。包装不同；写作方式相同：同样的杠杆让每一份都可预测——智能体每次运行都采用相同的*流程*，而不是产生相同的输出。

当你编写的文档是技能时，请阅读 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md) 以了解 frontmatter、调用选择和路由器技能。

## 上下文指针

**上下文指针**是保存在智能体上下文中的一种引用，它指明某些上下文之外的材料，并编码到达该材料的条件。技能的描述就是其中之一；`AGENTS.md` 中指明某文档的一行也是同一个物件。决定智能体何时到达材料——以及多可靠地到达——的是指针的*措辞*，而不是其目标。一个措辞软弱的指针后面的必读目标是方差缺陷：先加强措辞，只有在加强失败时才将材料内联。

指针做两件事——说明材料是什么，并列出应触发到达该材料的**分支**（分支是文档处理的独特情形，因此不同的运行会走不同的路径）。始终加载的指针的每个词在每一轮都花掉成本，所以它比正文更该被狠狠修剪：

* **前置关键词**——指针就是做触发工作的地方。
* **每个分支一个触发器。** 为单个分支换名的同义词是同一个分支写了两次；合并它们，只保留真正不同的分支。
* **\*\*删掉正文已经携带的标识。\*\***

## 两种负载

你添加的每份文档和指针都会花掉两种预算之一：

* **上下文负载** — 始终加载的材料在智能体窗口上的成本：`AGENTS.md` 的一行、技能描述、任何每轮都坐在上下文中的东西，无论是否触发都消耗 token 和注意力。
* **认知负载** — 对人产生的成本：存在哪些文档、何时取用每一份。人就是索引。这不是要最小化的成本——它是人的能动性的代价；把它花在人的判断重要的地方，在无关紧要的地方移除它。

仅通过指针到达的材料以指针自身那一行为代价摆脱了上下文负载；完全没有指针的材料则完全由认知负载承担。

## 信息层级

文档由两种内容类型构建——**步骤**（智能体按顺序执行的动作）和**参考**（按需查阅的定义、规则、事实）——它们可以自由混合：全步骤（食谱）、全参考（评审规则、本技能）、或两者兼有。核心决策是每一块在**信息层级**上处于什么位置，这个阶梯按智能体需要材料的紧急性排序：

1. **文件内步骤** —— 主要层级：智能体按顺序做什么。
2. **文件内参考** —— 按需查阅。通常是合格的扁平同级集合（评审的每条规则都在同一档）——很好的安排，不是坏味道。
3. **披露参考** —— 被推入单独文件，通过上下文指针到达，只在指针触发时加载。涵盖从同一文件夹中的同级文件，一直到位于任何地方、任何文档都能指向的完全外部参考。

往下推得太少，顶部臃肿；推得太多，你就藏起了智能体真正需要的材料。这种张力就是整个决策。

**渐进式披露**是沿阶梯下行——移出主文件、放到指针后面——这样顶部保持清晰可读。这主要不是 token 优化：这是保护层级的方式。分支是最干净的披露检验：每个分支都需要的内容内联，只有部分分支会触及的内容放到指针后面。当文档有步骤时，那些应被披露的文件内参考会埋没步骤，把对步骤的专注变成抛硬币——这是方差杠杆，不只是可读性杠杆。

\*\*共位（Co-location）\*\*是文件内的伴侣原则：阶梯决定一块内容*沉到多深*，共位则决定一旦到了那里*什么与它并排*。把概念的定义、规则和注意事项放在同一个标题下而不是散落各处，这样读到一部分时就会带上它的邻居。检验标准：文档读起来应该像为智能体编写的文档——分组的材料读起来如此；分散的材料则不然。（不同于重复：重复是在两处重复同一含义；分散是把一个含义碎片化到多处。）

\*\*蔓延（Sprawl）\*\*是这里的失败模式：文档就是太长，即使每一行都有效且独特。注意力在多余中变稀，每多一行就多一行要保持相关。解药是阶梯：把参考披露到指针后面，按分支或序列拆分，使每条路径只携带它需要的。

## 步骤与完成标准

每个步骤都以**完成标准**结束——告诉智能体工作完成的条件。两个属性使它成为杠杆：

* **清晰度** — 智能体能分辨完成与未完成吗？模糊的界限（"理解已达成"）会招致**过早完成**：在真正完成之前结束步骤，注意力滑向*已经完成*。仍然可见的前方步骤——**完成后步骤**——提供拉力；标准的清晰度就是阻力。按顺序防御：**先强化界限**（局部而廉价）；只有当界限不可化约地模糊*并且*你观察到赶工，才通过拆分序列隐藏后续步骤——而隐藏只在真正的上下文边界处有效（交接或子智能体派遣；内联调用会让后续步骤留在上下文中，什么都清不掉）。
* **要求度** — 它要求做多少。"每个修改过的模型都交代清楚"迫使彻底工作，而"生成变更列表"则不会。要求度驱动**苦功（legwork）**——智能体在任务内部做的挖掘，隐含在措辞中而不是写成独立的步骤——而且它不限于步骤："每条规则都已应用"约束一整套扁平参考，正如"每一步都已完成"约束一个序列，这正是全参考文档仍然带有穷尽性标准的方式。

最强的标准既可检查又穷尽。

## 何时拆分

把一份文档拆成两份会花掉两种负载之一，所以只在拆得值得时才拆：

* **按序列** — 在完成后步骤会诱使智能体赶工眼前步骤的地方，拆分一段步骤。让它们保持不可见，能驱动对当前任务做更多苦功。当心反面：合并序列会让每个步骤的后续步骤暴露给后面跟着的东西，招致过早完成。
* **按调用** — 技能特有：参见 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)。

## 引导词

**引导词**是已经活在模型预训练中的紧凑概念，智能体执行文档时用它来思考（*lesson*、*fog of war*、*tracer bullets*）。作为 token 重复、从不作为句子重复，它积累出分布式的定义，并以最少的 token 锚定一整块行为区域，方法是调动模型已有的先验。自己造词也行，只要你定义清楚，但造出来的词调动不了任何先验——预训练的词免费给你的东西，你得用定义 token 来付；先去找现成的词。

它锚定两次。在正文中，*执行*：词每次出现，智能体都会调用相同的行为；在扁平参考内部，它把注意力聚焦到要找的那一类事物上。在指针中，*调用*：当同一个词存在于你的提示词、文档和代码库中时，智能体把这份共享语言与材料相连，更可靠地到达它。

寻找用引导词重构的机会。一个在三处写明的三元组、一个花一句话指向同一想法的指针——每一处都是渴求坍缩成单个 token 的段落：

* "fast, deterministic, low-overhead" → *tight*（一个 *tight* 循环）。
* "a loop you believe in" → *red* — 模糊的门变成二进制的可观察状态（循环在 bug 上变 *red*，或者不变）。

你赢两次：更少的 token，以及一个更锋利的钩子供智能体挂起它的思考。假设每份文档都带着可以被引导词退役的复述——去找出它们。

**否定**是这个杠杆旁的失败模式：用禁止来引导，会把被禁止的行为拖进上下文，使它*更*可用，而不是更不可用。*别想大象*，于是满脑子都是大象；否定是个弱修饰语，被强烈激活的概念会压过它，所以禁令有一半会被读成去做那件事的指示。提示**正向**——陈述目标行为（"写单行注释"），这样被禁的那个永远不被说出。禁令只有在你无法正向表述的硬护栏情形下才配得上存在；即便如此，也要把它与正向目标配对，让注意力落在该做什么上。

## 修剪

* 将每个含义保持在**单一事实来源**中：一个权威的位置，这样更改行为只需在一处编辑。**重复**——同一含义出现在多个位置——会增加维护成本和 token，并让含义在阶梯上的显著性超过其实际等级。（这是引导词的意外反面；引导词刻意重复 token，而从不重复含义。）
* **环境**也是事实来源——`package.json` 脚本、配置文件、目录结构、`--help` 输出——而重述这些内容的文档是一种**缓存**：查找结果的副本，只有在查找成本高时才值得加载。缓存那些智能体无法通过查看找到的内容：未成文的约定、选择背后的原因、任何配置都不会坦白的陷阱。把单文件、单命令的查找留给环境，它们在那里不会过时。
* 逐行检查**相关性**：它是否仍然与文档所做的事情相关？一行文字如果始终与任务无关（纯粹铺陈，或本应披露的分支），或者随着其描述的行为或世界变化而过时，就会失去相关性。更短的文档更容易保持相关性。没有修剪纪律，默认的归宿是**沉积物**：陈旧的层次不断堆积，因为添加让人安心，删除让人冒险，直到你必须从中钻探下去才能找到仍然有生命力的内容。
* 逐句搜捕**无效指令（no-op）**：模型默认就会遵守的指令，付出加载成本却什么也没说。检验标准——与默认行为相比，它是否改变了行为？——是相对于模型而非读者的：两个人对 no-op 有分歧，实际上是对默认行为有分歧，应该通过运行文档来解决，而不是争论。当一句话不合格时，删除整句，而不是删减其中的词语。这一标准也用于衡量引导词：一个不足以击败默认行为的词（当智能体已经足够 thorough 时写 *be thorough*）是 no-op，解决办法是换一个更强的词（*relentless*），而不是换一种技巧。
