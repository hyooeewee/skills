用户请求进行 **回顾**。您正在建议改进编码代理的 **环境**，以提高未来的运行效果。

## 步骤

1. 调用 Skill 工具并使用 `writing-for-agents` 获取写作风格指南。

2. 阅读用户指定的会话的主要来源。这可能意味着在此机器上搜索会话日志。如果用户未指定会话，则默认为当前会话。

3. 在这些类别中寻找改进候选项。

* **导航**：代理找到正确文件的难度如何？文件之间是否存在隐藏依赖关系？**导航指针**是否会让事情变得更简单？*在以下情况下使用*：会话花费很长时间才找到某条信息。
* **自动化检查**：是否存在可以捕获代理错误的自动化检查？代码检查、类型检查、测试、文件系统检查器？*在以下情况下使用*：代理犯了错误，而该错误本可以通过自动化检查被发现。
* **编码标准**：是否应该为 **审查代理** 添加新规则来强制执行？是否应该删除或阐明现有规则？*在以下情况下使用*：审查代理未能发现错误。
* **全局 AGENTS.md**：是否有任何引导指令应该移动到编码标准（或自动化检查）中？*在以下情况下使用*：AGENTS.md 文件特别大 - 在仓库或用户的全局作用域中。
* **工具经济性**：代理是否进行了可以精简的昂贵工具调用？是否有任何自定义工具（CLI、MCP）特别不节省令牌？*在以下情况下使用*：代理进行了昂贵的工具调用。
* **无操作**：在引导文件中寻找不会修改代理行为的指令。*在以下情况下使用*：引导文件庞大且难以管理。
* **信息访问**：寻找增加代理信息访问机会的地方。重定向开发服务器日志，只读访问第三方服务。*在以下情况下使用*：关键信息代理无法获取。

4. 按严重程度向用户展示这些候选项。

## 参考

### 实现与审查

请记住，所有工作都经过两个阶段：实现和审查。实现代理承受最大的 **上下文压力**。它们负责探索、编写代码和调试失败。

审查代理承受的上下文压力最小 - 它接收差异，因此无需探索。它通常不需要编写代码或进行调试。

这意味着审查代理应该负责强制执行编码标准，而不是实现代理。

### 文件

您有权访问仓库中的几个文件：

* `CLAUDE.md`/`AGENTS.md`：这些文件被推送到在此仓库中工作的任何代理的上下文窗口中。应非常谨慎地使用它们，通常仅用于指向其他文件的 **导航指针**。
* `CODING_STANDARDS.md`：此文件在审查期间读取，而不是在实现期间读取。如果标准文件超过 1,000 行，请向文档文件夹添加 **导航指针**。
* Docs: use docs as references files, pointed to by other files. Look for existing docs before writing new ones.
* Skills：将 skills 用于文档（因为其描述进入代理的上下文窗口），或用于用户调用的命令。遵循 `writing-for-agents` skill 中的建议。
